## Feature Breakdown

### 1. Heartbeat System (Proactive Awareness)

**Source:** OpenClaw - https://github.com/openclaw/openclaw

#### Core Concept
Heartbeat runs periodic agent turns in the main session, allowing the model to surface attention-requiring items without spamming the user.

#### Implementation Plan

**Phase 1: Core Infrastructure**
- [ ] Add `heartbeat` configuration to `config.json`
- [ ] Implement heartbeat scheduler (default: 30m interval)
- [ ] Create `HEARTBEAT.md` template system
- [ ] Add `HEARTBEAT_OK` response handling

**Phase 2: Delivery System**
- [ ] Implement target routing (`last`, `none`, channel-specific)
- [ ] Add active hours restriction (configurable timezone)
- [ ] Implement visibility controls (showOk, showAlerts, useIndicator)
- [ ] Add typing indicators for heartbeat runs

**Phase 3: Advanced Features**
- [ ] Add `lightContext` mode (only HEARTBEAT.md from bootstrap)
- [ ] Implement `isolatedSession` for token efficiency
- [ ] Add `skipWhenBusy` for constrained hosts
- [ ] Implement manual wake system (`system event`)

#### Configuration Schema
Compatible with existing `core/config/settings.py` structure:
```json
{
  "agents": {
    "defaults": {
      "heartbeat": {
        "every": "30m",
        "target": "last",
        "lightContext": false,
        "isolatedSession": false,
        "skipWhenBusy": false,
        "activeHours": {
          "start": "08:00",
          "end": "22:00",
          "timezone": "America/New_York"
        },
        "prompt": "Read HEARTBEAT.md if exists. Follow strictly. If nothing needs attention, reply HEARTBEAT_OK.",
        "ackMaxChars": 300
      }
    }
  }
}
```
**Integration Note:** The heartbeat config extends the existing agents configuration block. The `HeartbeatScheduler` class will read from `settings.agents.defaults.heartbeat` (same pattern as existing config access in `core/config/settings.py`).

#### HEARTBEAT.md Format
Supports two modes:
1. **Checklist mode** - Simple markdown checklist
2. **Tasks block mode** - Structured intervals:
```markdown
tasks:
- name: inbox-triage
  interval: 30m
  prompt: "Check for urgent unread emails and flag anything time sensitive."
- name: calendar-scan
  interval: 2h
  prompt: "Check for upcoming meetings that need prep or follow-up."
```

## Technical Architecture Additions

### Event-Driven System
```python
# Heartbeat triggers
@on_event("heartbeat_tick")
async def periodic_check():
    await self.check_schedule()
    await self.update_memory()
    await self.create_skills_from_recent()

# Learning triggers
@on_event("task_completed")
async def learn_from_task(task_data):
    if self.tool_call_count > 5:
        await self.create_skill_document(task_data)
```

### Session Management
Leverages existing `core/memory/conversation_manager.py` with extensions:
- **Main Session**: Persistent identity, memory, skills (existing `ConversationManager`)
- **Heartbeat Sessions**: Isolated runs with `lightContext` (new `isolatedSession` mode)
- **Task Sessions**: Detached work with task records (extends existing task system)
- **Subagent Sessions**: Parallel workstreams (new multi-agent feature)

**Integration:** Heartbeat sessions use `ConversationManager` with `max_history=10` and `lightContext=True` to minimize token usage while maintaining context for `HEARTBEAT.md` processing.
